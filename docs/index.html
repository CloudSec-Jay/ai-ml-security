The premise

An AI agent is a principal with instructions, tools, credentials, and access to untrusted context. Its security boundary is wider than the model and narrower than the infrastructure around it.

This project follows the full decision path: how an attacker reaches the agent, what the agent is allowed to call, how artifacts are verified, and which evidence an operator needs afterward.

The agent is treated as a workload identity, not a trusted user. One role per purpose, explicit tool scope, controlled paths, and recorded calls reduce the impact of manipulated instructions.

Tool descriptions, retrieved documents, model artifacts, and plugin packages remain untrusted until their provenance and permissions are reviewed.

03

From attack to control

  1. 01

    Reproduce

    Start with an explicit attack input and observable model or agent behavior.

  2. 02

    Locate the boundary

    Identify which instruction, tool, identity, package, or data path was trusted incorrectly.

  3. 03

    Constrain capability

    Reduce permissions and validate context at the narrowest useful enforcement point.

  4. 04

    Preserve evidence

    Record the agent identity, input, tool call, output, and resulting system action.

04

Current state

Controls in source.
Validation continues.

The repository contains working prompt-injection examples, threat models, MCP review material, identity guidance, model-integrity controls, and Kubernetes MLOps security design.

Several areas remain intentionally incomplete, including broader red-team missions, output-validation implementations, agent audit trails, and end-to-end detection evidence. The source distinguishes built artifacts from roadmap work.
